Embed charts in static sites

Astro, Hugo, Eleventy, Jekyll, Next static export — ship real charts as HTML + CSS with no client-side chart library. Better first paint, simpler builds, stronger SEO.

Why static sites and JS charts clash

Static generators excel at shipping HTML and CSS. Most chart libraries expect a browser runtime: download JS, hydrate, then draw. That adds weight, delays LCP, and leaves crawlers waiting.

ProvChart generates the chart ahead of time. You commit or build the markup once; the live page only paints CSS. No Chart.js, no Highcharts, no hydration step for the graphic.

Three ways to embed

1 Visual builder (fastest)

Use the free builder, copy HTML + CSS, paste into a layout or Markdown shortcode. Ideal for docs, marketing pages, and one-off charts.

2 Build-time API call

In CI or a local script, POST /api/v1/generate, write chart.html / chart.css (or one partial), then include them in the generator. Best when data comes from JSON, CMS, or a spreadsheet at build time.

3 Partial + known data

Keep series in front matter or a data file; run a small Node script on prebuild to refresh snippets. Keeps content in git and charts reproducible.

Minimal embed pattern

<!-- In your page or component -->
<figure class="chart-embed">
  <figcaption>Revenue by month</figcaption>
  <div id="chart-root">
    <!-- paste ProvChart HTML here -->
  </div>
</figure>

<style>
  /* paste ProvChart CSS here, or link a built chart.css */
</style>
Accessibility: Add a short summary and a data table. See Accessible charts.

Build-time generation (Node)

// scripts/generate-charts.mjs
const API = "https://provchart-api.devtem.org/api/v1/generate";
const KEY = process.env.PROVCHART_API_KEY;

const payload = {
  type: "line",
  series: [
    { name: "Revenue", color: "#8b7bff", points: [20, 35, 48, 66] }
  ],
  axisX: ["Jan", "Feb", "Mar", "Apr"],
  theme: "dark"
};

const res = await fetch(API, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-API-Key": KEY
  },
  body: JSON.stringify(payload)
});

const data = await res.json();
if (!data.success) throw new Error(data.error);

import { writeFileSync } from "fs";
writeFileSync("src/partials/chart-revenue.html", data.html);
writeFileSync("src/styles/chart-revenue.css", data.css);

Hook with "prebuild": "node scripts/generate-charts.mjs". Keep the key in CI secrets — never in the public repo.

Per generator

Astro

Put HTML in a .astro component or import a partial. Scope CSS with a layout import or <style is:global> if the chart classes are global (pc-*).

Hugo

Save snippets under layouts/partials/charts/ and CSS under assets/css/ or static/. Call with {{ partial "charts/revenue.html" . }}.

Eleventy (11ty)

Use _includes/charts/revenue.html and add the CSS to your cascade. Optional: an 11ty shortcode that reads the prebuilt file.

Jekyll

Includes in _includes/, CSS in the theme pipeline or assets/. Front matter can hold captions; the chart body stays in the include.

Next.js static export

Generate files in scripts/ before next build. Import CSS from public/ or the app stylesheet. Avoid calling the API from client components in production.

SEO benefits

  • Chart structure is in the first HTML response
  • No “empty div until JS runs”
  • Works with text alternatives and tables for accessibility and crawlers
  • Smaller JS payload → better CWV on content sites

When you still need client JS

Live filters, streaming points, or rich brush/zoom interactions may need a JS library or your own controls. For docs, blogs, landing pages, and most marketing dashboards, static CSS charts are enough — link “Explore live” to an app route if needed.

Checklist

  • Generate at build time or paste from the builder
  • API key only in CI / server env
  • Caption + summary + data table
  • Theme aligned with the site (light/dark)
  • Cache or commit snippets so rebuilds are reproducible
