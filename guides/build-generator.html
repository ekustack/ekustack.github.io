Guide

Build your own CSS chart generator

Use the ProvChart Developer API to power a chart tool for your product, docs, or internal dashboards. Users get pure HTML + CSS charts — zero chart library on the page.

What you’re building

A small app (web UI or backend service) that:

  1. Collects chart type + data (form, API, or CMS)
  2. Calls POST /api/v1/generate
  3. Receives { html, css }
  4. Injects or stores that output for embed / preview

The browser never runs a charting library — only your generator does, via the API.

Roadmap

  • Phase 1 API key + one working fetch that returns a line chart. Paste HTML/CSS into a static page.
  • Phase 2 Simple UI: type select, series inputs, Generate button, live preview + copy buttons.
  • Phase 3 Themes, multiple series, error handling, usage display from GET /api/v1/usage.
  • Phase 4 Save presets, export as snippet, optional auth for your users, rate-limit messaging.
  • Phase 5 Server-side generation (Node/Python) for emails, PDFs, or static site builds.

Step-by-step setup

1 Get an API key

Sign in at the dashboard → Developer API → Create key. Free accounts get a few test generations; Pro/Business unlock monthly quotas.

2 Call the generate endpoint

POST https://provchart-api.devtem.org/api/v1/generate
Header: X-API-Key: YOUR_API_KEY
Body: JSON with type, series, optional axisX and theme.

3 Inject the result

Put data.html in a container and append <style>${data.css}</style> to <head> (or store both for later embed).

Minimal working example

<div id="chart"></div>

<script type="module">
  const API_KEY = "YOUR_API_KEY";

  const res = await fetch("https://provchart-api.devtem.org/api/v1/generate", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "X-API-Key": API_KEY
    },
    body: JSON.stringify({
      type: "line",
      series: [
        { name: "Revenue", color: "#8b7bff", points: [20, 35, 48, 66] },
        { name: "Users", color: "#4fd8c4", points: [12, 28, 41, 55] }
      ],
      axisX: ["Jan", "Feb", "Mar", "Apr"],
      theme: "dark"
    })
  });

  const data = await res.json();

  if (data.success) {
    document.getElementById("chart").innerHTML = data.html;
    document.head.insertAdjacentHTML("beforeend", `<style>${data.css}</style>`);
  } else {
    console.error(data.error);
  }
</script>

Building a simple generator UI

Suggested layout:

  • Left panel: chart type, series list (name, color, points), X labels, theme
  • Right panel: live preview + HTML/CSS code blocks with Copy

On Generate: build the payload from the form → call the API → inject preview and fill the code blocks. Keep series as an array you can add/remove in the UI (same pattern as the Pro Dashboard).

Payload shape (reminder)

{
  "type": "area",
  "series": [
    { "name": "Organic", "color": "#8b7bff", "points": [18, 28, 35, 42] }
  ],
  "axisX": ["Mon", "Tue", "Wed", "Thu"],
  "theme": "dark",
  "stacked": false
}

Supported types: line, area, bar, stackedbar, hbar, scatter, combo, gauge. See API docs.

Pro tips

Never expose your secret key in public frontend code for production. For public apps, proxy through your backend: browser → your API → ProvChart (key stays on the server).
Check usage before heavy loops. Call GET /api/v1/usage and show remaining quota so users aren’t surprised by MONTHLY_LIMIT_REACHED.
Cache successful outputs. Same data + type + theme → same HTML/CSS. Cache by hash of the payload to save generations.
Validate points client-side. Empty series, non-numeric values, or huge arrays waste quota. Enforce max points (e.g. 200) before calling the API.
Match your product theme. Pass a custom theme object (bg, surface, text, muted, grid, radius) so generated charts blend into your UI.
Handle errors softly. Map INVALID_API_KEY, PLAN_REQUIRED, and MONTHLY_LIMIT_REACHED to clear UI messages (and a link to upgrade or the dashboard).
Start with one chart type. Ship line + bar first; add area, gauge, scatter once the form and copy flow feel solid.
Offer both preview and embed. Preview for editing; a “Copy embed” snippet that includes a minimal wrapper + style tag for docs/CMS.
