Charts in Markdown & docs

Use POST /api/v1/generate-svg to embed charts in README files, GitHub/GitLab docs, and static documentation - as SVG markup or a data URI. No Chart.js, no screenshot service, no image CDN.

Quota: Successful SVG calls share the same monthly pool as HTML generate (5 when signed up free · 500 Pro · 5,000 Business). See pricing and API docs.

Why SVG for Markdown

  • Portable - works where Markdown allows images or raw HTML
  • No host - ProvChart does not store files; you paste or commit the result
  • Sharp at any zoom - vectors scale in docs sites
  • Same data model - same type, series, axisX as /generate

1. Get an API key

  1. Sign in → Pro Dashboard → Developer API
  2. Create a key (copy once)
  3. Send X-API-Key: pc_live_… on every request

Never commit live keys. Use CI secrets or generate SVG in a private pipeline and commit only the output.

2. Call generate-svg

curl -s -X POST "https://provchart-api.devtem.org/api/v1/generate-svg" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: YOUR_API_KEY" \
  -d '{
    "type": "line",
    "series": [
      { "name": "Stars", "color": "#8b7bff", "points": [12, 18, 25, 40, 55] }
    ],
    "axisX": ["Jan", "Feb", "Mar", "Apr", "May"],
    "width": 640,
    "height": 280
  }'

Response

{
  "success": true,
  "svg": "<svg xmlns=\"http://www.w3.org/2000/svg\" ...>...</svg>",
  "dataUri": "data:image/svg+xml;base64,..."
}

JavaScript

const res = await fetch("https://provchart-api.devtem.org/api/v1/generate-svg", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-API-Key": process.env.PROVCHART_API_KEY
  },
  body: JSON.stringify({
    type: "area",
    series: [{ name: "Views", color: "#4fd8c4", points: [10, 25, 40, 55, 48] }],
    axisX: ["Mon", "Tue", "Wed", "Thu", "Fri"],
    width: 640,
    height: 240
  })
});
const data = await res.json();
if (!data.success) throw new Error(data.error);
// data.svg | data.dataUri

3. Embed in Markdown

Option A - Data URI (quick demos)

![Stars over time](data:image/svg+xml;base64,PASTE_FROM_dataUri)

Fine for short SVGs. Some hosts truncate very long lines - if the README breaks, use Option B.

Option B - Commit an .svg file (recommended)

# save API svg field to docs/charts/stars.svg, then:
![Stars over time](./docs/charts/stars.svg)

Best for GitHub, GitLab, and most static doc generators.

Option C - Inline HTML (if your engine allows raw HTML)

<!-- Some docs engines (not GitHub README) allow: -->
<div>
  <!-- paste data.svg here -->
</div>

4. Dashboard shortcut

Pro Dashboard → Generate Chart SVG tab: paste your key, run a payload, preview, copy SVG or data URI. Usage still counts toward the monthly limit.

Supported types

Same as HTML API: line, area, bar, stackedbar, hbar, scatter, combo, gauge. Optional width / height (defaults 640×320; max 1200×800).

CI pattern (keep README fresh)

Use the official ProvChart README Charts GitHub Action (v1.0.3) to automatically generate vector charts from a configuration file and write them to your repository.

1. Chart Configuration

Add .provchart/charts.json:

{
  "charts": [
    {
      "file": "traffic.svg",
      "type": "area",
      "width": 640,
      "height": 240,
      "series": [
        { "name": "Traffic", "color": "#8b7bff", "points": [20, 35, 50, 65, 85] }
      ],
      "axisX": ["Mon", "Tue", "Wed", "Thu", "Fri"]
    }
  ]
}

2. GitHub Action Workflow (v1.0.3)

Add .github/workflows/update-readme-chart.yml:

name: Update ProvChart README SVGs

on:
  schedule:
    - cron: '0 0 * * *' # Daily at midnight
  workflow_dispatch:

jobs:
  update-chart:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Generate ProvChart SVGs
        uses: fscss-ttr/provchart-readme-action@v1.0.3
        with:
          api-key: ${{ secrets.PROVCHART_API_KEY }}
          config: '.provchart/charts.json'
          output-dir: 'docs/charts'

      - name: Commit and push updated chart
        uses: stefanzweifel/git-auto-commit-action@v5
        with:
          commit_message: "chore: update provchart README SVG [skip ci]"
          file_pattern: 'docs/charts/*.svg'

When to use HTML instead

  • Product UI / web apps → /api/v1/generate (HTML + CSS), better theming in-page
  • README / MkDocs / Docusaurus static assets → /generate-svg
  • Email - client support for SVG varies; this guide is for docs/Markdown, not email HTML

Troubleshooting

  • Image broken in README - data URI too long; switch to a committed .svg file
  • 401 - check X-API-Key and that the key was not revoked
  • 429 MONTHLY_LIMIT_REACHED - upgrade or wait for month reset; check GET /api/v1/usage
  • Empty chart - ensure series[].points and matching axisX
Security: Use repository secrets for keys. Commit only SVG/HTML output, never pc_live_ secrets.
