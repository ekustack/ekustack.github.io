Guide

Interactive charts at 100 performance

Interactive visuals and a strong Lighthouse run do not have to fight each other. Paint charts with HTML and CSS on the first response, then add tooltips and motion as progressive enhancement—so Core Web Vitals are not held hostage by a chart library.

Disclaimer: No stack guarantees a permanent “100” score—images, fonts, and third parties still matter. Removing chart-runtime JavaScript from the critical path is one of the highest-leverage wins on metric-heavy pages.

The real performance problem

Core Web Vitals care about main-thread work and when useful pixels appear. A typical JS chart stack downloads a library, parses it, then draws—often leaving an empty region until script finishes.

Cost JS chart library Paint-first (ProvChart)
Download / parse Library + adapters No chart library required for paint
First paint Often after JS runs Chart HTML/CSS in the first response
SEO / first crawl Hydration-dependent Markup present immediately
Interaction Bundled with the library Optional small runtime

Pipeline: compile → paint → enhance

01 Compile

Turn JSON into scoped HTML and CSS via the builder or Developer API—not a client chart framework.

02 Paint

Inject CSS + HTML. The browser draws with custom properties and native geometry (clip-path, bars, gauges).

03 Enhance

Optionally load provchart-runtime for tooltips, reveal, and legend focus. Charts still work if it never loads.

Compile — API example

const res = await fetch("https://provchart-api.devtem.org/api/v1/generate", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-API-Key": process.env.PROVCHART_API_KEY
  },
  body: JSON.stringify({
    type: "area",
    series: [
      { name: "Traffic", color: "#4fd8c4", points: [30, 45, 40, 60, 55, 70, 65] },
      { name: "Signups", color: "#f0a860", points: [8, 12, 11, 18, 16, 22, 20] }
    ],
    axisX: ["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"]
  })
});

const data = await res.json();
if (!data.success) throw new Error(data.error);

Paint — inject

document.head.insertAdjacentHTML(
  "beforeend",
  `<style id="provchart-style">${data.css}</style>`
);
document.getElementById("chart").innerHTML = data.html;

Enhance — optional runtime

<script>
  window.ProvChartRuntimeConfig = {
    animation: true,
    revealOnScroll: true,
    tooltips: true,
    perPointTooltips: true,
    observe: true,
    excludeSvg: true
  };
</script>
<script
  src="https://cdn.jsdelivr.net/npm/provchart-runtime@1.2.0/dist/provchart-runtime.min.js"
  defer></script>
Rule: Rendering must not depend on the runtime. If the script 404s, the chart should still be visible and correct.

What “interactive” can mean without a heavy library

Need Lightweight approach
Hover values Runtime tooltips / hit targets
Legend focus Dim other series on legend hover
Live data Rewrite CSS variables or re-generate
README / docs POST /api/v1/generate-svg → commit .svg
Brush / zoom / streaming JS library on that route only

Checklist toward a top performance score

  1. No chart library on the critical path — generate HTML/CSS at build time or via API; ship only scoped CSS.
  2. Defer enhancement — use defer for runtime; visible chart without it.
  3. Honor prefers-reduced-motion — runtime should skip transform theatre when requested.
  4. Own LCP honestly — hero images and fonts often dominate; optimize them separately.
  5. Font-display — use swap (or equivalent) so text and labels do not block paint indefinitely.
  6. Split the product — paint-first charts on public/KPI pages; heavy analytics libs only where interaction earns the KB.
  7. Accessibility — short summary + optional data table ( accessible charts guide).

Static sites, CI, and agents

  • SSG: generate at build time; commit HTML/CSS or call the API in CI.
  • README: prefer file embeds over huge data URIs ( charts in Markdown).
  • Agents: stable JSON in → markup out—easy for ChatGPT/Claude tools without a browser chart API.

When a JavaScript chart library still wins

  • Brushing, zooming, linked crossfilters
  • High-frequency streaming ticks
  • Exotic types outside the CSS engine’s scope

Use those tools deliberately on routes that justify the cost—not as the default for every sparkline.

Verify

  1. Load the page with JS disabled (or block the runtime)—chart still visible.
  2. Mobile Lighthouse: watch JS execution time and LCP.
  3. Confirm tooltips only after runtime loads (enhancement, not requirement).
