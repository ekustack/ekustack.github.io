Lightweight analytics with ProvChart + Claude

Ship a fully responsive analytics view with almost no dependencies: HTML/CSS for layout, ProvChart for charts, Claude (or MCP) to draft payloads. No React, no Chart.js. Paint first, enhance later.

Goal: KPI row + one or two charts that work on mobile and desktop, stay fast on first paint, and stay editable by an agent when metrics change.

Dependency budget

Piece Required? Role
HTML + CSS Yes Responsive shell (grid / flex)
ProvChart API Yes html + css for each chart
API key Yes Server or build-time; avoid public bundles in production
provchart-runtime No Tooltips / motion only
Claude + provchart-mcp No Author payloads or call generate tools
React / Vue / Chart.js No Not needed for this pattern

Architecture

  1. Layout: static markup: header, KPI cards, chart panels.
  2. Data to chart JSON: you, your backend, or Claude.
  3. Compile: POST /api/v1/generate (or MCP provchart_generate).
  4. Paint: inject CSS + HTML into each panel.
  5. Enhance: optional Runtime 1.2.0 + refresh().

Prompt Claude

With MCP connected:

Build JSON for a midnight-themed analytics page:
1) area chart: traffic + signups, last 7 days, realistic counts
2) bar chart: revenue by channel (Organic, Paid, Partner, Other)

Use provchart_generate for both. I will inject html/css into divs
#chart-traffic and #chart-revenue.

Without MCP, ask for the JSON only and call the API yourself.

Responsive layout (idea)

  • KPIs: 2 columns on small screens, 4 from \~720px up
  • Charts: stacked on mobile, two columns from \~800px up
  • Panels: min-height so the page does not jump while generating

Generate + inject

const res = await fetch("https://provchart-api.devtem.org/api/v1/generate", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-API-Key": process.env.PROVCHART_API_KEY
  },
  body: JSON.stringify({
    type: "area",
    theme: "midnight",
    series: [
      { name: "Visitors", color: "#8b7bff", points: [4200, 5100, 4800, 6200, 5900, 7100, 6800] },
      { name: "Signups", color: "#4fd8c4", points: [320, 410, 380, 520, 490, 610, 580] }
    ],
    axisX: ["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"]
  })
});

const data = await res.json();
document.head.insertAdjacentHTML(
  "beforeend",
  `<style>${data.css}</style>`
);
document.getElementById("chart-traffic").innerHTML = data.html;
window.ProvChartRuntime?.refresh?.();
Production: proxy generate on your server so PROVCHART_API_KEY never ships to the browser.

Optional runtime

<script>
  window.ProvChartRuntimeConfig = {
    tooltips: true,
    perPointTooltips: true,
    observe: true,
    excludeSvg: true
  };
</script>
<script
  src="https://cdn.jsdelivr.net/npm/provchart-runtime@1.2.0/dist/provchart-runtime.min.js"
  defer
></script>

Charts remain visible if the script fails. Guide: How to set up ProvChart Runtime.

What belongs in the page vs the agent

You maintain Claude can draft
Grid, spacing, brand colors Series names, points, axis labels
Auth / API proxy Alternate chart types (bar vs area)
KPI number formatting rules Sample dashboards for demos

When to add more dependencies

  • Complex client routing and shared state: a small framework may help
  • Brush, zoom, streaming ticks: a JS chart library on that route only
  • README metrics: generate-svg + GitHub Action instead of live HTML

Checklist

  1. Page readable with JS disabled except missing live charts
  2. Key not in a public repo
  3. Mobile: KPIs wrap; charts stack
  4. Lighthouse: no multi-hundred-KB chart vendor on the critical path
  5. Agent path documented for your team (/agents)
