Email charts with the ProvChart API

Map analytics data to pure-CSS charts, generate them on the server, and ship clear snapshots in weekly digests — without putting a chart library in the inbox.

Why email is different

Most chart libraries need JavaScript. Email clients don’t run it. ProvChart returns HTML + CSS. You generate that on the server from your analytics, then either rasterize to an image (most reliable) or use a tightly controlled snippet where clients allow it.

The inbox never sees your API key — only a static chart and a link back to the live dashboard.

The flow

  1. Pull analytics for the period (API, warehouse, or DB)
  2. Map rows → ProvChart payload (type, series, axisX, theme)
  3. POST /api/v1/generate with your API key
  4. Turn html + css into a PNG (or store the snippet)
  5. Embed in the email template + CTA to the full dashboard

Map analytics → payload

Keep one mapper so every report shares the same shape:

function analyticsToPayload(report) {
  return {
    type: "line",
    series: [
      {
        name: "Revenue",
        color: "#8b7bff",
        points: report.revenueByDay.map(d => d.value)
      },
      {
        name: "Orders",
        color: "#4fd8c4",
        points: report.ordersByDay.map(d => d.value)
      }
    ],
    axisX: report.revenueByDay.map(d => d.label),
    theme: {
      bg: "#0c0a16",
      surface: "#1a1628",
      text: "#eae7f5",
      muted: "#837da0",
      grid: "#8b7bff",
      radius: "12px"
    }
  };
}

Swap the data source; keep the function. Weekly, monthly, and alert emails stay consistent.

Skip dense scatter or multi-combo in email — save those for the product UI.

Ten practical tips

1 Generate on the server

Never call the API from the email client. Your send job (or worker) owns the key, the payload, and the output.

2 Prefer images for clients

Path: analytics → API → html/css → headless render (Playwright/Puppeteer) → PNG → CDN → <img> in the template. Works in Gmail, Outlook, and Apple Mail.

3 Design for one glance

One question per chart: “Did revenue rise?” “Which channel led?” Cap series (1–2) and points (7–14 days). Put the headline metric in the subject or preheader.

4 Cache by payload hash

Same type + series + labels + theme → same output. Cache html/css or PNG so repeats don’t burn quota or re-render.

5 Check usage before bulk sends

GET /api/v1/usage — if remaining is low, drop optional charts or fall back to number-only blocks. Don’t hit MONTHLY_LIMIT_REACHED mid-campaign.

6 Theme for email, not the admin UI

Higher contrast, backgrounds that match the template (white or your brand dark). Use a dedicated theme object for digests vs in-app charts.

7 Always add a CTA

Under the chart: “Full dashboard →” linking to the live product. Email is the snapshot; the app is where they explore.

8 Keep a single weekly layout

Hero metric → one trend chart → one breakdown → three bullets → CTA. Change data, not structure, so every send feels on-brand.

9 Validate before you generate

Empty series, non-numeric points, or huge arrays waste generations. Enforce max points and required fields in the mapper.

10 Proxy the key

Production frontends should not hold the secret key. Browser → your backend → ProvChart keeps credentials off the client.

Minimal server sketch

const payload = analyticsToPayload(weeklyReport);

const res = await fetch("https://provchart-api.devtem.org/api/v1/generate", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-API-Key": process.env.PROVCHART_API_KEY
  },
  body: JSON.stringify(payload)
});

const data = await res.json();
if (!data.success) throw new Error(data.error);

// Option A: rasterize data.html + data.css → PNG → upload → <img src="...">
// Option B: store snippet for a web version of the same report

Do / Don’t

Do

  • Generate server-side
  • Map analytics → fixed payload
  • Cache by hash
  • Prefer line / bar / gauge
  • Link to the live dashboard

Don’t

  • Call the API from the inbox
  • Ad-hoc JSON every send
  • Regenerate identical charts
  • Pack five dense series into a digest
  • Expect full interactivity in email
