How to set up ProvChart Runtime

There is almost no setup step. You include a CDN script; it scans the page for ProvChart markup and attaches interaction. It does not render or re-render charts. ProvChart does not depend on it—Runtime only makes the page feel interactive.

One sentence: Paint with HTML/CSS first; load Runtime second (or never). Charts stay correct either way.

Why Runtime exists

ProvChart’s job is paint: data becomes scoped HTML and CSS. Hover values, scroll reveal, and legend focus are nice—but they are not required to show a correct chart.

Runtime exists so you can:

  • Keep the critical path free of a chart-library bundle
  • Add tooltips and motion as progressive enhancement
  • Ship the same markup to users who block scripts

Without Runtime you still have a chart. With Runtime you get interaction on top.

What Runtime does not do

Not Runtime’s job Who does it
Draw bars, lines, areas, gauges Generated HTML + CSS (API or builder)
Re-render when data changes You re-inject HTML/CSS or update variables
Replace SVG from generate-svg Excluded by default (excludeSvg: true)
Require npm or a bundler Optional; CDN is enough

Setup (really just include)

  1. Have ProvChart HTML on the page (data-provchart nodes + their CSS).
  2. Optionally set window.ProvChartRuntimeConfig.
  3. Load the script with defer.

Minimal

<script
  src="https://cdn.jsdelivr.net/npm/provchart-runtime@1.2.0/dist/provchart-runtime.min.js"
  defer
></script>

With config (recommended defaults)

<script>
  window.ProvChartRuntimeConfig = {
    animation: true,
    revealOnScroll: true,
    replay: false,
    hoverScale: 1.02,
    tooltips: true,
    perPointTooltips: true,
    countUp: true,
    countUpMs: 800,
    observe: true,
    selector: "[data-provchart]",
    excludeSvg: true,
    durationMs: 700
  };
</script>
<script
  src="https://cdn.jsdelivr.net/npm/provchart-runtime@1.2.0/dist/provchart-runtime.min.js"
  defer
></script>

On load, Runtime finds matching nodes, enhances them, and can watch the DOM (observe: true) for charts injected later.

After client-side inject

If you fetch HTML/CSS and set innerHTML after the script already ran, call refresh: 

document.getElementById("chart").innerHTML = data.html;
// css already in a <style> tag
window.ProvChartRuntime?.refresh?.();

Where it works best

  • Area and line — per-point tooltips and hover targets feel natural
  • Bar / hbar / combo / gauge — supported on HTML output
  • Pure SVG exports — skipped when excludeSvg is true (README embeds stay static)

npm (optional)

npm install provchart-runtime@1.2.0

Or use jsDelivr / unpkg as above. Repo: github.com/fscss-ttr/provchart-runtime

Config reference (short)

Option Default Role
tooltips / perPointTooltips true Value tooltips on hover
animation / revealOnScroll true Entrance motion
observe true MutationObserver for late inject
selector [data-provchart] What to enhance
excludeSvg true Skip pure SVG charts

JS API

Call When
ProvChartRuntime.scan() Manual full scan
ProvChartRuntime.refresh(root?) After dynamic HTML inject
ProvChartRuntime.enhance(el) One node
ProvChartRuntime.destroy() Tear down observers

Checklist

  1. Chart visible with Runtime blocked or removed
  2. Script loaded with defer, config defined before the script tag
  3. refresh() after SPA / fetch inject
  4. Do not expect Runtime to fix missing CSS or empty series
