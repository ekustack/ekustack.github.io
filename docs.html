Overview

ProvChart turns data into pure CSS charts (HTML) or static SVG. After generation, the browser paints the chart. A heavy chart-library runtime is not required.

Optional Runtime 1.2.0 adds tooltips and motion for HTML output only.

  • HTML + CSS — apps, dashboards, marketing pages
  • SVG — README, docs, Markdown
  • API base — https://provchart-api.devtem.org
  • CI — GitHub Actions for config charts and repo health

Builder: /get-started · Dashboard: /dashboard · Guides: /guides

Quick start

  1. Open Dashboard → Developer API and create a key.
  2. Call POST /api/v1/generate from a server with X-API-Key.
  3. Inject returned html and css into the page.
  4. (Optional) Load Runtime 1.2.0 for tooltips.
const res = await fetch("https://provchart-api.devtem.org/api/v1/generate", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-API-Key": process.env.PROVCHART_API_KEY
  },
  body: JSON.stringify({
    type: "line",
    theme: "midnight",
    series: [
      {
        name: "Revenue",
        color: "#8b7bff",
        points: [1200, 1850, 2400, 3100]
      }
    ],
    axisX: ["Q1", "Q2", "Q3", "Q4"]
  })
});

const data = await res.json();

if (!data.success) {
  throw new Error(data.error);
}

// data.html  data.css

Concepts

  • Paint-first — CSS custom properties and native browser paint
  • Keys stay server-side — proxy, edge function, or CI secret
  • Scoped output — each chart instance has its own classes and variables
  • HTML vs SVG — interactive pages vs docs and README embeds

Value ranges

Values are not locked to 0–100. Use real metrics (counts, currency, latency, and so on).

  • Omit min / max — range is inferred from data (baseline defaults to 0 unless values go negative)
  • Set min / max — fix the axis explicitly
  • Stacked bars — max uses stacked totals when stacking is enabled
  • Labels and tooltips — large numbers format as k, M, B
{
  "type": "bar",
  "min": 0,
  "max": 5000,
  "series": [
    {
      "name": "Users",
      "color": "#8b7bff",
      "points": [820, 1400, 2100, 3600]
    }
  ],
  "axisX": ["Jan", "Feb", "Mar", "Apr"]
}
API limits: up to 200 points per series. Max series: free 1 · pro 12 · business 50.

Developer API

Base URL: https://provchart-api.devtem.org

Method Path Returns
POST /api/v1/generate html, css
POST /api/v1/generate-svg svg, dataUri
GET /api/v1/usage plan, used, limit, remaining
POST / GET / DELETE /api/v1/keys Key management (session JWT)

HTML and SVG generations share the same monthly quota.

Authentication 

X-API-Key: pc_live_xxxxxxxx

Authorization: Bearer pc_live_xxxxxxxx
Never put live keys in public frontend bundles. Use a server route, edge function, or CI secret.

POST /api/v1/generate

Returns scoped HTML and CSS for embedding in pages.

{
  "success": true,
  "html": "<div class=\"pc-...\" data-provchart=\"line\">...</div>",
  "css": ".pc-... { ... }"
}

POST /api/v1/generate-svg

Same chart body as generate. Optional width and height. Nothing is stored on a CDN.

{
  "success": true,
  "svg": "<svg xmlns=\"http://www.w3.org/2000/svg\" ...>...</svg>",
  "dataUri": "data:image/svg+xml;base64,..."
}

API keys

  • Create, list, and revoke in Dashboard → Developer API
  • Full key is shown once at creation
  • Revoked keys return INVALID_API_KEY

Integration pattern

Keep the API key on a server or in CI. Call ProvChart there. Return HTML/CSS to the client, or write SVG files into the repo.

Vanilla HTML 

<div id="chart"></div>
<style id="pc-style"></style>

<script type="module">
  const res = await fetch("/your-server-proxy", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      type: "line",
      series: [
        { name: "A", color: "#8b7bff", points: [10, 20, 30] }
      ],
      axisX: ["A", "B", "C"]
    })
  });

  const data = await res.json();

  document.getElementById("chart").innerHTML = data.html;
  document.getElementById("pc-style").textContent = data.css;

  window.ProvChartRuntime?.refresh?.();
</script>

Next.js 

// app/api/chart/route.ts

export async function POST(req: Request) {
  const body = await req.json();

  const res = await fetch("https://provchart-api.devtem.org/api/v1/generate", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "X-API-Key": process.env.PROVCHART_API_KEY!
    },
    body: JSON.stringify(body)
  });

  const data = await res.json();
  return Response.json(data, { status: res.status });
}

The browser calls /api/chart, injects html/css, then runs ProvChartRuntime.refresh() if Runtime is loaded.

Astro / SSG

Call the API in a build script or server endpoint. Inline the CSS and place the HTML in the page partial. No client chart library is required for first paint.

Workflow

name: Generate ProvChart SVGs

on:
  push:
    paths:
      - ".provchart/**"
      - ".github/workflows/charts.yml"
  workflow_dispatch:

permissions:
  contents: write

jobs:
  build-charts:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: fscss-ttr/provchart-readme-action@v1.0.4
        with:
          api-key: ${{ secrets.PROVCHART_API_KEY }}
          config: .provchart/charts.json
          output-dir: docs/charts

      - uses: stefanzweifel/git-auto-commit-action@v5
        with:
          commit_message: "chore: update ProvChart SVGs"
          file_pattern: "docs/charts/*.svg"

Runtime 1.2.0

Optional client script for HTML charts only. Adds scroll reveal, hover scale, per-point tooltips, legend focus, and count-up. Does not enhance pure SVG from generate-svg.

npm: provchart-runtime@1.2.0 · GitHub · npm

Runtime config 

<script>
  window.ProvChartRuntimeConfig = {
    animation: true,
    revealOnScroll: true,
    replay: false,
    hoverScale: 1.02,
    tooltips: true,
    perPointTooltips: true,
    countUp: true,
    countUpMs: 800,
    observe: true,
    selector: "[data-provchart]",
    excludeSvg: true,
    durationMs: 700
  };
</script>

<script
  src="https://cdn.jsdelivr.net/npm/provchart-runtime@1.2.0/dist/provchart-runtime.min.js"
  defer
></script>

Tooltips prefer real values from data-value and data-pc-sN, then format with the same k / M / B rules as axis labels.

AI agent guide

  • Base: https://provchart-api.devtem.org/api/v1
  • Auth: X-API-Key: pc_live_...
  • HTML: POST /generate → inject html and css
  • SVG: POST /generate-svg → file or dataUri
  • Use real numbers; optional min and max
  • Maximum 200 points per series
  • Do not retry 401 or 429 without new credentials or backoff
  • Call from a server or tool runtime — do not embed user keys in public pages

MCP

provchart-mcp exposes generate and generate-svg tools for agent hosts. Set environment variable PROVCHART_API_KEY.

Theming

  • Presets: dark, light, midnight
  • Or pass an object: bg, surface, muted, text, grid, radius, fontFamily

Troubleshooting

  • Empty chart — check series[].points and axisX
  • Odd axis scale — set min / max or review stacked totals
  • 401 — wrong or revoked key
  • 429 — call GET /usage; upgrade or wait for month reset
  • CI 403 with “Just a moment…” — Cloudflare bot challenge; allow automation on /api/*
  • No tooltips — load Runtime 1.2.0 after HTML inject, then call refresh()
  • Action missing api-key — repository secret named exactly PROVCHART_API_KEY
