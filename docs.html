What we solve

Heavy charts create the same three problems.

ProvChart’s pipeline is built to remove them - not paper over them with another runtime.

Bundle & LCP

js-class libraries add tens of KB and delay first paint. We never ship a chart runtime to the browser.

→ compile + paint

SEO & crawlers

Canvas-only charts are invisible on first crawl. Our output is HTML and CSS in the initial response.

→ index

Embeds & pipelines

Docs, SSGs, and READMEs need markup - not a client SPA. API returns HTML/CSS or SVG; no upload step.

→ generate + embed

Render pipeline

Four steps. That’s the whole engine.

Not a metaphor - the order the browser (and your build) actually run.

01. compile

Data - CSS variables

Points become --p1…--pN (or structured HTML/SVG from the API). Shape logic does not live in a charting framework on the client.

02. paint

Browser draws the geometry

clip-path, bars, and gauges use native CSS. First paint includes the chart - no “empty box until JS loads.”

03. index

Crawlers and a11y see structure

Markup is in the HTML response. Pair with captions and tables (accessible charts guide).

04. update

New data = variable writes

Optional JS only sets CSS variables (or you regenerate). No virtual DOM chart tree, no library re-mount.
